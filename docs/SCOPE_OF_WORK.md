## Objective

The scope of work for AI Cyber Security Services is to develop and package a combined AI security portfolio that illustrates how AI can be governed, protected, and operationalized safely across governance, compliance, simulation, and security operations.

## Included workstreams

### 1. AI security architecture design

- design of safe AI execution models
- separation of untrusted and trusted AI functions
- deterministic and semantic guardrail strategies

### 2. Red-team simulation and evaluation

- adversarial prompt generation
- risk taxonomy modeling
- security scenario simulation
- severity classification and escalation logic

### 3. Governance and compliance intelligence

- asset-to-control mapping
- policy and risk alignment
- telemetry-driven compliance checks
- governance issue identification and tracking

### 4. Security operations workflow

- evidence extraction and normalization
- event bundling and traceability
- MITRE-aligned reasoning references
- human approval gating for automation

### 5. Documentation and publishing readiness

- project README and architecture explanation
- compliance and policy documentation
- copyright and innovation disclosure
- thesis-ready market and technical commentary

## Exclusions

The following are outside the initial project scope unless expressly added by client or stakeholder agreement:

- production-grade enterprise deployment into live operational networks
- integration with production SIEM or ticketing systems
- production data classification and legal review for regulated environments
- long-term managed security services operation
- end-to-end deployment in regulated cloud environments without governance review

## Deliverables

- consolidated product README
- visual banner and product icon
- compliance checklist and compliance document
- copyright notice
- patent and invention disclosure
- future enhancement roadmap
- request for proposal package
- publishable Medium article

## Assumptions

- project work is exploratory and demonstration oriented
- source material is intended for research and prototyping
- production deployment requires additional security, legal, and operational validation
